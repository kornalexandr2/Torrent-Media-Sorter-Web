# Руководство разработчика (Torrent Media Sorter Web)

## Архитектура системы интернационализации (I18n)

В проекте реализована гибкая система мультиязычности, которая охватывает веб-интерфейс, API-ответы и системное логирование.

### 1. Хранение переводов
Все строки хранятся в формате JSON в папке `app/locales/`.
- `ru.json` — основной файл (русский язык).
- `en.json` — английский язык.

**Добавление нового языка:**
1. Создайте файл `app/locales/xx.json` (где `xx` — код языка).
2. Скопируйте структуру из `en.json` и переведите значения.
3. Язык автоматически появится в интерфейсе.

### 2. Использование в Backend (Python)
Для доступа к переводам используется глобальный объект `translator` из `app.core.i18n`.

```python
from ..core.i18n import translator

# Простой перевод
text = translator.translate("dashboard", lang="ru")

# Перевод с параметрами
text = translator.translate("log_proc_complete", lang="en", count=5)
```

### 3. Использование в шаблонах (Jinja2)
В шаблонах доступна глобальная функция `_()`, которая автоматически определяет язык из Cookies пользователя.

```html
<!-- Обычный текст -->
<h1>{{ _("settings_title") }}</h1>

<!-- Текст с параметрами -->
<p>{{ _("log_param_changed", key="host", old="localhost", new="127.0.0.1") }}</p>
```

### 4. Умное логирование (Database Logs)
Чтобы история обработки объектов переводилась на язык пользователя "на лету", логи сохраняются в базу данных в специальном формате:
- Если запись статична, сохраняется просто ключ (например, `log_obj_discovered`).
- Если запись содержит переменные, она сохраняется как JSON-строка: `{"key": "log_proc_complete", "params": {"count": 5}}`.

Для отображения таких логов в интерфейсе используется функция `render_log(line)`, которая:
1. Пытается распарсить строку как JSON.
2. Если успешно — вызывает `translator.translate` с параметрами.
3. Если это обычный текст — ищет его как ключ в словаре.

### 5. API и Cookies
Язык пользователя хранится в Cookie `lang` (срок жизни 30 дней). Маршрут `/set-lang/{lang}` отвечает за переключение.

## Стандарты разработки
- **Никогда** не пишите кириллицу (или жестко заданный английский текст) напрямую в Python-коде для сообщений, которые видит пользователь. Используйте ключи.
- При добавлении нового функционала обязательно добавляйте соответствующие ключи во все файлы в `app/locales/`.
- Логи в `sys_logger.log` также должны использовать ключи для обеспечения полной локализации системы.
